# xcode 세션

워크스페이스의 **xcode 세션 만들기** 또는 폴더의 **+ → xcode 세션**으로 시작한다. **세션 설정 펼치기**에서 API 주소(Chat Completions 전체 주소), API 토큰(선택), 모델명을 입력한 뒤 메시지를 전송한다. 모델명은 서버가 노출하는 모델 ID다. 기본 주소는 `http://127.0.0.1:8000/v1/chat/completions`다. 원격 서버에는 HTTPS를 사용한다. 고급 설정에서 기존 Builder 모델 프로필 선택, 동시 요청 수, 연결 진단, 자동 재요청, 하네스를 조정할 수 있다. 주소와 모델명은 세션에 자동 저장된다. 직접 입력한 토큰은 화면을 떠나면 지워진다. **이 기기에 토큰 저장**을 누르면 운영체제 암호화 저장소로 보호된 모델 프로필이 생성되고, 세션에는 프로필 이름만 저장된다. 저장된 토큰은 해당 주소와 모델명이 일치할 때 사용한다.

## settings.json으로 연결하기

**세션 설정 펼치기 → JSON 설정**에서 직접 붙여넣거나 **설정 파일 불러오기**로 파일을 선택한 뒤 **JSON 적용**을 누릅니다. 적용한 값은 기본 설정과 고급 설정에도 반영됩니다.

```json
{
  "endpoint": "http://127.0.0.1:8000/v1/chat/completions",
  "model": "my-model",
  "autoRetry": true,
  "retrySeconds": 60,
  "maxAutoRequests": 3
}
```

필수 항목은 `endpoint`와 `model`입니다. 인증이 필요하면 문자열 `token`을 추가하세요. **현재 설정 내보내기**는 토큰을 제외한 적용값을 저장합니다. 토큰을 생략하면 입력 중인 토큰을 유지합니다. 프로토콜·호스트·포트가 바뀌면 새 서버 주소를 확인하고 **이 토큰 사용**을 눌러야 전송할 수 있습니다. 선택 항목 `autoRetry`와 `repeatCompleted`는 true/false, `retrySeconds`는 1–3600초, `maxAutoRequests`는 1–100회, `autoMinutes`는 1–240분입니다. 생략한 재요청 옵션은 기존 값을 유지합니다.

잘못된 JSON이나 범위를 벗어난 값은 적용 전에 표시됩니다. 전송 시 401/403이면 토큰·권한, 404이면 주소·모델명을 확인하세요. 400/422이면 고급 설정의 텍스트 연결 진단으로 기본 요청을 먼저 확인한 후 이미지·PDF와 추론 옵션을 확인하세요.

사이드바를 접으면 현재 워크스페이스의 xcode 세션이 두 개 이상일 때 상단의 세션 이름으로 대화를 전환할 수 있습니다.

## 대화와 첨부

전송하면 지정한 서버가 SSE로 돌려주는 답변을 표시한다. 중지할 수 있으며 완료한 요청·첨부 참조·단계별 결과는 워크스페이스 페이지에 저장한다. 다음 요청은 기본적으로 이전 대화와 첨부를 다시 포함한다. 하네스에서 최근 대화 수를 지정하면 전송 범위를 줄일 수 있다. 이미지·PDF 원본은 보관함 첨부에 보관하며, 공유 워크스페이스에서는 해당 공간의 동기화 정책을 따른다.

| 입력 | 서버에 보내는 형식 |
| --- | --- |
| UTF-8 소스·Markdown·CSV·로그 | 파일명과 텍스트 |
| DOCX·PPTX·XLSX | 단락·슬라이드 텍스트 또는 셀 주소와 저장된 값. 도형, 임베디드 이미지, 수식 재계산은 제외 |
| PNG·JPEG·WebP·GIF | 이미지 입력을 지원하는 서버에 Chat Completions의 image_url 데이터로 전달 |
| PDF | file_data를 지원하는 서버에 원본 전달. 서버의 PDF 처리 능력에 따라 사용 가능 |

파일 선택과 끌어놓기를 지원한다. 클립보드의 이미지는 메시지 영역에 붙여넣는다. 텍스트 문서는 파일당 8MB 및 추출 후 16만 자, 이미지·PDF는 파일당 12MB, 모델 요청은 전체 32MB가 상한이다.

## 병렬 실행과 자동 재요청

같은 워크스페이스에서 페이지마다 독립적인 요청을 실행한다. 페이지를 바꾸어도 응답은 원래 페이지에 저장된다. 사이드바의 **실행 중인 xcode 세션**에서 돌아가 진행 상태를 확인하거나 해당 요청만 중지할 수 있다. 앱을 닫거나 워크스페이스를 바꾸면 실행과 예약은 종료된다.

자동 재요청은 기본으로 꺼져 있으며 설정은 페이지별로 저장된다. 기본 간격은 60초다. **중단된 응답만 이어받기**는 일시적인 서버 오류, 연결 끊김, 출력 길이 제한 후 이미 받은 텍스트와 함께 ‘계속해주세요’를 보낸다. **정상 완료 후에도 계속 요청**은 하네스를 마친 뒤에도 간격마다 같은 대화에 ‘계속해주세요’를 보내며, 완료된 답변을 하나씩 저장한다. HTTP 429, 사용량·잔액 초과, 인증 실패 등은 자동으로 반복하지 않는다. 재요청을 끄면 다음 예약이 취소되고, **중지**는 실행 중인 요청도 취소한다.

## 하네스

직무 역할 22종과 작업 템플릿 29종을 조합한다. 예를 들어 SRE와 장애 회고, QA와 회귀 테스트 설계, 비즈니스 분석가와 Word 양식 작성안을 함께 선택할 수 있다. 역할은 모든 단계에 적용되며 템플릿을 바꿔도 유지된다. 채팅 하네스에서는 작성안을 확인하고, 양식 파일로 저장하려면 Word·Excel 양식 채우기를 사용한다. 단계를 추가·삭제·재정렬하고 각 단계의 지침을 편집한다. 한 번 전송할 때마다 단계별로 모델을 호출하며 다음 단계는 앞선 단계의 답을 받는다. 서버 기본 추론 강도를 사용하거나 지원되는 값을 명시할 수 있다. 템플릿을 바꾸면 현재 하네스 구성이 교체된다. 하네스 JSON 내보내기·가져오기로 다른 세션에서 재사용할 수 있다.

**.claude 스킬 찾기**는 사용자 홈과 로컬 워크스페이스의 `.claude/skills/<이름>/SKILL.md`를 찾는다. 추가한 지침의 사본이 하네스에 저장되고 모델 요청에 포함된다. 스킬의 부속 스크립트·훅 실행, 셸 및 프로젝트 파일 자동 수정은 이 버전의 실행 범위 밖이다.

## DeepSeek 업무별 기본 구성

새 세션은 단일 호출로 근거 기반 답변을 작성한다. 변경안 작성과 인프라 의사결정에는 근거 추출, 설계·작성, 검토 세 단계를 제공한다. 시각 자료 판독은 관찰과 해석 두 단계다. 추출·관찰 단계에 low, 작성·판단·검토 단계에 high를 지정한 것은 xdocs의 업무별 설계 선택이다. 하네스와 각 단계에서 변경할 수 있으며, 추론 옵션을 받지 않는 서빙 엔드포인트는 단계별로 **서버 기본값**을 선택한다.

같은 요청의 여러 단계는 스킬, 전체 단계 지침, 과거 대화와 첨부를 같은 순서로 공유한다. 뒤 단계에서는 앞 단계의 답과 다음 단계 번호를 이어 붙인다. 이 구조는 prefix caching이 활성화된 서빙 엔진에서 공통 입력을 재사용할 수 있게 한다. 실제 캐시 사용 여부는 서버 설정에 달려 있다. 이전 턴에서는 최종 답을 넘긴다. 도구 호출 없는 텍스트 대화에는 모델 내부 추론 텍스트를 재전송할 필요가 없다.

## 전송 및 자동 요청 관리

앱을 실행한 후 처음 사용하는 모델 주소는 전송 전에 확인합니다. 허용은 해당 주소에만 적용되며 앱을 종료하면 초기화됩니다. 자동 요청 횟수는 직접 전송할 때마다 새로 계산합니다. 오류 재시도와 정상 완료 후 이어쓰기가 같은 한도(기본 5회)를 사용합니다. 사이드바의 실행 중인 세션 목록에서 현재 워크스페이스의 모든 요청과 대기를 중지할 수 있습니다.

전송 버튼 옆의 **전송 미리보기**에서 주소와 모델을 확인하고, 이번 요청에 포함할 이전 대화·이전 첨부·새 첨부·스킬을 선택할 수 있습니다. 제외한 새 첨부는 입력란에 남습니다. 각 요청의 결과에는 실행 당시 모델, 하네스와 스킬 이름, 단계별 추론 설정·재시도 횟수·경과 시간이 저장됩니다.

서버 동시 요청 수는 같은 서버 주소(프로토콜·호스트·포트)를 사용하는 세션에 함께 적용됩니다. 기본은 2개이며 1~8개 사이로 설정합니다. 대기 중인 세션은 도착 순서로 실행되며 사이드바에서 개별 또는 전체 중지할 수 있습니다. 자동 실행 한도는 첫 자동 대기부터 계산하며 기본 15분입니다. 한도에 도달하면 자동 요청의 대기와 수신을 중지합니다.

모델 연결에서 텍스트·샘플 이미지·샘플 PDF 중 하나를 선택하고 **연결 진단 실행**을 누르면 해당 모델에 테스트 요청 1건을 보냅니다. 진단은 현재 대화나 첨부를 포함하지 않으며, 이미지와 PDF는 샘플 안의 문자 판독 결과도 표시합니다.

## 중단된 실행과 입력 범위

개인 워크스페이스에서는 실행에 사용한 메시지, 모델, 하네스와 완료한 단계를 기기의 복구 저장소에 기록합니다. 앱을 다시 열어 원래 페이지의 **미완료 단계부터 재실행**을 누르면 마지막으로 완료한 단계 다음부터 시작합니다. 수신 중이던 부분 응답을 먼저 확인할 수 있습니다. 재실행은 모델 서버에 별도 요청을 보냅니다. 현재 주소와 모델이 저장 당시와 같아야 하며, 필요한 API 키는 다시 입력할 수 있습니다. 정상 저장 후 해당 실행의 복구 기록을 지웁니다.

**프로젝트 파일 선택**에서 폴더를 열고 파일과 줄 범위를 선택합니다. 선택한 텍스트와 경로가 첨부되며, 전송 미리보기에서 제외할 수 있습니다. 바이트 표시는 선택 텍스트의 UTF-8 크기입니다. 토큰 수와 이미지·PDF 크기는 모델과 서버에 따라 달라집니다.

Builder의 **xcode 단계 지침 내보내기**로 저장한 JSON은 xcode의 **하네스 가져오기**에서 엽니다. Builder 규칙의 이름·지침·열·기준값을 단계 프롬프트로 변환합니다. Builder의 결정적 계산, 조건부 중단은 Builder 실행기에 남습니다.

## Windows에 열려 있는 Word 문단 편집

1. 개인 워크스페이스의 xcode 메시지 입력란 아래에서 **Word 선택 영역 → Windows 도우미 저장**을 누릅니다. 같은 Windows PC면 개인 폴더를, Ubuntu VMware에서 Windows 호스트의 Word를 쓰면 양쪽에서 접근할 수 있는 개인 공유 폴더를 고릅니다.
2. Windows 데스크톱 Word에서 편집할 본문을 선택합니다. 같은 Windows 사용자 계정의 Windows PowerShell 5.1에서 해당 폴더로 이동해 `.\xdocs-word.ps1`을 실행합니다. 조직에서 PowerShell 실행을 관리한다면 승인된 실행 절차를 사용하세요.
3. **Word 선택 영역 가져오기**에서 도우미가 만든 선택 영역 JSON 파일을 선택합니다. 선택한 텍스트와 문서 이름이 첨부됩니다. 지시를 입력하고 전송하면 세션의 모델이 첨부 내용을 받습니다.
4. 답변이 오면 **최근 답변 사용**으로 수정안을 채우거나 직접 입력해 편집합니다. **Word에 수정안 보내기**를 누른 뒤 Windows의 확인 창에서 승인합니다. Word에서 결과를 확인하고 저장하세요.

도우미는 한 번에 본문 선택 영역 하나(최대 5만 자)를 처리하며 30분간 기다립니다. 수정안은 일반 텍스트입니다. 선택 영역이 달라지거나 보호된 문서이면 교체하지 않습니다. 공유 폴더의 원문·수정안 파일은 도우미가 종료 시 정리하며, 강제 종료로 남은 파일은 직접 삭제할 수 있습니다. 첨부하여 전송한 텍스트는 xcode 세션 기록에 남습니다.

### 로컬 문서 첨부

채팅의 **파일 첨부**에서 HWPX 본문, OpenDocument 텍스트·프레젠테이션(ODT·OTT·ODP·OTP), Office 문서와 양식(DOCX·DOTX·PPTX·POTX·XLSX·XLTX)을 선택할 수 있습니다. 본문·셀 텍스트를 기기에서 추출해 전송할 때 세션의 모델 서버에 보냅니다. 파일당 8MB 및 추출 텍스트 16만 자 한도가 적용됩니다. 레이아웃·도형은 재현하지 않습니다. 구형 바이너리 HWP는 HWPX로 저장해 첨부하세요.

### 양식에 근거 자료 반영하기

일반 채팅에 Word 양식과 회의록·CSV·Excel을 첨부하고 “이 양식을 채워줘”라고 요청합니다. Word 파일이 여러 개면 양식 파일명을 적으세요. 데스크톱에서는 절대 경로를 입력한 뒤 파일 선택 창에서 양식을 확인할 수도 있습니다. 응답을 받으면 필드별 값, 모델이 제시한 출처와 충돌을 검토하고 **작성본 사본 저장**을 누릅니다. 수동으로는 **클립 → Word·Excel 양식 채우기**에서 원본을 선택할 수 있습니다.

기본 Word 양식은 본문·머리말·꼬리말의 `{{ 필드명 }}` 및 항목명 오른쪽의 빈 표 칸, 일반 텍스트 콘텐츠 컨트롤을 지원합니다. 세 개 이상의 밑줄 문자로 표시한 후보는 검토 화면에서 체크한 곳만 채웁니다. Excel은 표시되는 시트의 자리표시자와 파일에 존재하는 빈 셀을 사용합니다. 빈 셀이 파일에 저장되도록 입력란에 서식을 지정하세요. 수식, 보호된 시트 및 병합 영역의 보조 셀은 입력 대상에서 제외합니다.

조건문이나 반복 행이 있는 Word 양식은 선택한 모델에서 JSON 값만 받고 데스크톱에서 python-docx-template로 처리합니다. 앱 전용 환경에 패키지가 없으면 사용자에게 설치 확인을 요청합니다. Python 3 및 venv 지원, 최초 설치 시 PyPI 연결이 필요합니다. 취소 후 기존 채팅과 기본 양식을 계속 사용할 수 있습니다. 설치 후 렌더링은 기기에서 실행됩니다.

### 대기 메시지

응답 중에도 다음 메시지를 작성하고 파일을 첨부할 수 있습니다. Enter를 누르면 현재 세션의 대기열에 추가됩니다. Shift+Enter는 줄바꿈입니다. 입력창 위의 **대기 메시지**를 펼치면 전송 전 내용을 수정하거나 취소할 수 있습니다. 대기열에 넣지 않은 초안은 답변이 끝나도 입력창에 남습니다.

현재 답변이 세션에 저장된 뒤 다음 메시지를 보냅니다. 다른 세션을 열어도 진행 중인 세션은 자신의 대기열을 처리합니다. 요청 실패·중지 또는 앱 재시작 후에는 내용을 확인하고 **대기열 재개**를 누르세요. 응답 도중 연결이 끊긴 경우 서버가 이미 처리한 요청은 재시도 시 다시 처리될 수 있습니다.

중단된 메시지는 **이 메시지 재시도**로 이어가거나 **건너뛰고 다음 전송**으로 제외합니다. 대기 항목의 위·아래 화살표로 순서를 변경할 수 있습니다. 세션 목록과 접힌 메뉴의 세션 탭에는 남은 대기 건수가 표시됩니다. 대기 중에 모델이나 서버 주소가 바뀌면 등록 당시 설정과 현재 설정을 확인하고 **이 메시지에 현재 설정 적용**을 누른 항목만 새 대상으로 전송할 수 있습니다.

### 대화 검색과 재사용

입력 중인 첨부와 양식은 이 기기에 초안으로 보존됩니다. 응답 중 Enter는 대기열에 추가합니다. 전송 옵션의 **지금 이어서 요청**은 수신 중인 답을 보존하고 새 지시를 먼저 실행합니다. 대화 찾기(Ctrl/⌘+F)로 질문·답변 단위를 탐색하고 Esc로 원래 읽던 위치로 돌아갑니다. 답변에서 문장을 선택해 인용하거나 답변 메뉴에서 해당 시점의 새 세션 또는 연결된 노트를 만드세요.

새로 첨부한 Word·Excel 문서에서 모델이 `[보고서.docx#문단 2]`, `[예산.xlsx#비용!B2:C4]` 형식으로 인용하면 xdocs가 추출 위치를 확인해 원문을 펼쳐 줍니다. 첨부 당시 내용이 기준입니다. 모델 입력 한도에 걸리면 **전송 범위 줄이기**에서 이전 대화와 첨부를 선택해 같은 요청을 재시도할 수 있습니다.

### 워크스페이스 자료와 답변 반영

입력창에서 **@**를 입력하거나 첨부 메뉴의 **워크스페이스 페이지**를 엽니다. 노트는 본문, 시트는 지정한 탭의 셀 범위, xinfra는 선택한 리소스와 해당 Terraform 선언을 미리 보고 첨부합니다. 시트 범위는 A1 표기법으로 최대 1만 셀까지 지원합니다. 출처 패널은 넓은 창에서는 답변 오른쪽에, 좁은 창에서는 아래에 열립니다. 선택 범위 밖의 셀 값은 첨부에 포함되지 않습니다.

첨부한 페이지가 수정되면 **원본 변경됨**에서 전송 당시 사본과 최신 선택 범위를 비교할 수 있습니다. 새로 작성하는 질문에 어느 버전을 포함할지 선택하세요. **답변 메뉴 → 기존 노트에 반영**에서는 끝에 추가하거나 바꿀 블록을 고른 뒤 변경 내용을 확인해 저장합니다. 미리보기 후 원본이 수정되면 다시 불러와야 합니다.

대기 메시지의 **실행 설정**에서 모델, 역할과 단계를 확인합니다. 새 항목은 등록 당시 하네스로 실행하며, 항목별로 **실행 시 세션 설정**을 선택할 수 있습니다. 이전 버전에서 등록해 하네스가 기록되지 않은 항목은 세션 설정을 사용합니다.

**원본 열기**로 셀 범위나 xinfra 리소스를 확인하고 **대화로 돌아가기**로 읽던 위치에 돌아옵니다. 답변에서 필요한 부분을 선택한 뒤 **선택한 부분 반영**을 누르세요. 여러 노트는 **검토 목록에 추가**하고 저장할 항목을 체크합니다. **노트 반영 이력**은 이 기기의 세션에 저장됩니다. 되돌리기 전에 차이를 확인하고, 같은 위치가 수정되었다면 되돌릴 내용을 직접 검토합니다.

Word·Excel 양식에서 확인된 출처를 펼치면 해당 셀이나 문단의 값이 보입니다. **근거 누락·충돌만 보기**로 모델이 보고한 충돌과 누락 또는 확인할 수 없는 출처를 검토합니다.

답변 메뉴의 **답변 블록 선택**에서 여러 문단·표·코드 블록을 골라 원래 Markdown 그대로 반영할 수 있습니다. **노트 반영 초안 이어서 검토**로 대상, 위치, 체크 상태를 복원합니다. 여러 노트를 저장하는 동안 원본이 바뀐 항목은 **최신본에서 재검토**로 이전 원본과 비교한 뒤 위치를 다시 지정합니다. 대상 노트의 **반영 출처**에서는 해당 세션의 답변으로 바로 이동합니다. 반영 초안과 출처 이력은 이 기기에 저장됩니다.

Word·Excel 필드의 출처를 펼치면 제안 값과 추출한 출처 값이 나란히 나타납니다. 숫자나 단위, 날짜가 일치하지 않는 필드도 **근거 누락·충돌만 보기**에 포함합니다. 표기만 다르고 같은 날짜는 같은 값으로 판단합니다.

**저장 전 미리보기**에서 Word·Excel 양식의 원본 값과 제안 값을 나란히 확인합니다. 반영할 필드를 고르고 검토 승인과 사유를 기록한 다음 **작성본 사본 저장**을 누르세요. 고급 Word 양식은 반복·조건에 전달되는 변수 단위로 선택합니다.

여러 노트를 저장하면 **노트 반영 결과**에서 완료·충돌·보류를 확인하고, 저장된 노트나 추가 검토할 항목을 열 수 있습니다. 대상 노트의 **반영 출처**는 해당 답변, 반영한 내용, 확인된 인용으로 이동합니다. **노트 반영 이력**의 **검토 기록 Markdown 저장**에는 변경 내역과 인용, 이 세션에서 최근 저장한 Office 검토 사유가 포함됩니다.

작성본 저장 전에 파일을 다시 열어 반영한 값, 제외한 입력 위치와 Excel 수식이 예상대로인지 검사합니다. 저장한 뒤에는 **저장한 작성본 검사**에서 파일을 직접 선택해 다시 확인할 수 있습니다. 고급 Word 반복·조건 양식은 문서 구조를 검사합니다. Office 검토 중인 값과 선택, 승인 사유는 양식별로 복원됩니다. 같은 이름의 원본이 바뀌면 추가·제거·재검토할 입력란을 확인하고 일치하는 항목만 가져올 수 있습니다.

**노트 반영 이력**에서 같은 저장 작업으로 반영된 여러 노트를 선택해 되돌릴 수 있습니다. 이후 편집과 겹치는 변경은 개별 미리보기에서 검토합니다. 사이드바 **검토 이력**은 워크스페이스에 속한 노트 반영과 저장하거나 내보낸 Office 검토 기록을 이름이나 출처로 검색합니다. 이전 버전에서 저장한 최근 Office 검토 기록도 표시합니다.
