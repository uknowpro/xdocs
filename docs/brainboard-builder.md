# Builder와 IaCD 후속 개발

## Builder 사용 흐름

워크스페이스에서 **Builder 만들기**를 누르거나 폴더의 **+ → Builder**로 페이지를 만든다. 시트의 첫 행은 열 이름이다. 월간 비용 검토는 선택한 열의 금액이 지정한 기준을 초과한 행을 찾는다. 데이터 품질과 자산 중복 예제는 각각 빈 값과 반복되는 값을 찾는다. 각 단계는 원본 전체 또는 직전 단계에서 검출된 행을 검사한다. 결과가 없을 때 중단하는 분기와 단계별 입력·검출 건수, 소요 시간을 확인할 수 있다. 시트 이름과 셀 주소를 표시하며 첫 200개를 초안에 수록한다.

회의 액션 아이템·장애 회고·요구사항 검토는 선택한 Markdown 노트를 줄 단위로 읽는다. 찾을 문구를 바꾸면 해당 줄 번호를 근거로 기록한다. 하네스 6종과 프롬프트 12종을 제공한다. 하네스 파일을 내보내거나 현재 워크스페이스에 이름을 붙여 사본을 저장하면 원본 입력 페이지 연결을 비우고 규칙과 지침을 복사한다.

단계를 추가·복제·재정렬하고 이름·판정 조건·모델 지침을 바꿀 수 있다. 프롬프트 방식을 선택한 뒤 문구를 수정한다. **SKILL.md 저장**과 **스킬 지침 가져오기**는 단계의 지침을 교환한다. 판정 조건과 단계 순서는 Builder 페이지에 저장한다.

데스크톱에서는 Chat Completions 호환 주소 전체와 모델 이름을 입력한다. 로컬 또는 사내 오픈웨이트 서버와 호환 상용 API가 대상이다. **전송할 지침과 셀 보기**에서 내용을 확인하고 **모델로 전송**한다. 선택 사항으로 Streamable HTTP MCP 서버의 텍스트 리소스를 읽어 참고 자료에 넣을 수 있다. MCP 액세스 토큰은 세션에서 입력하고, 서버가 읽기 전용으로 표시한 도구는 인자를 검토해 직접 호출한다. 모델 프로필은 기기에 저장하며 API 키는 사용자가 선택할 때 OS 암호화 저장소로 보호한다. 키·MCP 자료·모델 응답은 하네스 공유 파일에서 제외한다. **결과를 하위 노트로 저장**하면 선택한 결과와 현재 초안이 새 노트에 들어간다.

## Brainboard 검토

로그인된 AWS 서버리스 예제에서 리전, 개별 서비스, 템플릿의 공급자·공개 범위 필터와 리소스 설정 패널을 확인했다. 로컬 Chrome의 Templates 패널에서 검색·필터 아래에 도면 썸네일을 먼저 표시하고 바로 밑에 템플릿 이름과 작성자를 배치한 것을 확인했다. xdocs는 각 카드에 로컬 설계의 경계 도면 또는 Terraform 원본의 참조도, 이름, 공급자와 편집 방식을 표시한다. 아래의 상호작용은 공식 문서를 추가로 검토했다.

| 관찰 | xdocs 적용과 검증 기준 |
| --- | --- |
| 리소스를 선택하면 대응하는 코드가 강조되고 코드에서도 리소스를 선택할 수 있다. [리소스와 코드](https://docs.brainboard.co/cloud-architectures/cloud-resource) | 생성한 Terraform JSON의 실제 주소로 선언과 도형을 연결한다. 같은 이름의 다른 종류를 선택해도 올바른 블록을 열어야 한다. |
| 설정에서 생긴 연결과 사람이 그린 설명선은 의미가 다르다. 컨테이너 속성 상속에도 공급자별 제약이 있다. [노드 동작](https://docs.brainboard.co/cloud-design/design-area/node) | 소속·설정 참조·설명선을 구별한다. 설명선을 추가한 전후에 추출 파일이 같아야 한다. |
| 변수·로컬 값·출력과 리소스를 구별해 탐색한다. [입력과 출력](https://docs.brainboard.co/cloud-design/left-bar/input-and-output) | 선언을 종류별로 열고 복합 값도 보존한다. 이후 모듈 경로와 선언 위치를 함께 표시한다. |
| 버전에는 도면뿐 아니라 공급자와 파일 구성도 들어간다. [버전 관리](https://docs.brainboard.co/cloud-design/design-area/versioning) | 템플릿 버전에 입력·출력과 검증용 원본을 묶고, 사용자 수정과 템플릿 업데이트를 비교할 수 있게 한다. |

## 개발 순서

1. [x] Builder 시트 입력, 근거 셀, 결과 노트, 프롬프트·스킬 편집과 호환 모델 및 MCP 자료 조회.
2. [x] 공급자별 IaCD 템플릿 선택, 구성 리소스 미리보기, AWS·Azure·GCP 각각 3종의 Terraform 추출·재가져오기.
3. [x] Terraform JSON 선언과 캔버스 선택 연동. 생성 파일의 변수·로컬 값·출력 보기.
4. [x] HCL 가져오기 때 선언한 파일을 기록하고 파서로 확인된 단일 행 헤더는 줄 번호를 제공한다. 모듈의 같은 이름이 서로 다른 파일에 있는 예제로 파일·선언 위치를 확인한다.
5. [x] 기존 참조 목록에서 속성을 확인하고 경계 도면에 독립적인 설명선을 추가·삭제한다. AWS·Azure·GCP 각각에서 시각적 변경과 Terraform 변경을 비교한다.
6. [x] AWS Route Table, Azure Network Security Group, GCP Cloud Router를 팔레트에 추가했다. 세 유형의 속성·부모 경계·잘못된 배치·추출 후 역변환을 검증한다.
7. [x] AWS·Azure·GCP 각각 30종을 공급자·이름·리소스 유형으로 찾는다. 공급자마다 xdocs 컴포넌트 기반 3종과 원본 Terraform 기반 27종을 포함한다. 후자는 기존 Terraform 가져오기와 같은 편집 범위를 가지며, 가져온 원본과 라이선스 고지를 추출물에 포함한다. AWS는 이벤트 기반 서버리스 패턴, Azure는 허브·스포크와 관리형 서비스, GCP는 네트워크·데이터·서버리스 사례에 비중을 두었다. 샘플별 실제 배포에는 공급자가 요구하는 입력·리전·외부 서비스 확인이 필요하다. [원본 목록과 커밋](../catalog/sources.json)
8. WAF 운영 검토와 추출 보고서에 사용한 AVM 모듈·고정 버전을 기록한다. WAF 검토의 **AVM · Terraform 모듈 버전 비교**에서 같은 모듈의 현재 버전과 후보 버전에 대해 각각 생성한 terraform-docs JSON을 연다. 입력·출력 이름의 추가·삭제, 입력 유형과 필수 여부 변경을 비교한다. 기본값·검증식과 실제 배포 영향은 별도 검토가 필요하다.
9. 이름 있는 하네스 사본에 원본 페이지 ID와 저장 시점 버전을 기록한다. 워크스페이스 템플릿으로 게시하고 다른 Builder에서 해당 버전을 적용할 수 있다. 서로 다른 공간 사이에서는 하네스 파일을 사용한다. 기존 하네스 실행은 팀 원본 수정의 영향을 받지 않아야 한다.
10. 기기별 모델 프로필, OS 암호화 키 저장, MCP 토큰 인증과 명시적인 조회 도구 호출을 구현했다. 게시자와 실행자의 권한 차이는 두 계정에서 검증한다.
11. 이전 단계의 검출 행 전달과 빈 결과 중단을 지원한다. 외부 모델 요청 실패 후 같은 입력을 다시 보내거나, 저장된 대체 프로필의 모델·주소를 확인하고 수동 전송한다. 주소별 인증을 분리하며 결과 저장은 별도 동작이다. 취소와 재시도에서 같은 결과 노트가 중복 생성되는지 검사한다.
12. 카탈로그의 공급자·리소스명 검색, 단계별 소요 시간과 고정한 응답 비교를 제공한다. 응답 형식에서 **근거 목록 JSON 검증**을 선택하면 요약과 근거 배열의 형식을 확인하고, 입력에 없는 주소와 누락 주소를 표시한다. 모델 호환성 필터는 후속이다.
