# xdocs 사용·개발 가이드

## 실행과 플랫폼

Node.js 24 이상에서 `npm ci` 후 `npm start`로 실행합니다. 데스크톱 그래픽 환경과 한글 폰트가 필요합니다. `npm run dev`는 데모 데이터를 브라우저 저장소에 보관하는 UI 미리보기입니다.

Ubuntu 개발 환경에서 검증했습니다. macOS·Windows용 패키징 설정과 CI는 포함되어 있지만 실제 OS의 설치·서명 검증은 별도입니다.

## 노트 작성

1. 보관함 폴더를 열고 **+**로 노트를 만듭니다.
2. **편집하기**에서 Markdown 원문 또는 블록 편집을 선택합니다.
3. `[[노트 제목]]` 또는 블록 편집기의 링크 선택기로 연결합니다.
4. **연결 탐색**에서 제목·폴더·태그 필터로 그래프를 탐색합니다.
5. **내보내기**에서 Markdown·HTML·PDF를 저장합니다.

단축키: `Ctrl/Cmd + K` 검색, `Ctrl/Cmd + S` 저장, `Esc` 일반 대화상자 닫기.

### 블록 편집

제목·문단·굵게·목록·할 일·코드·표를 지원합니다. **블록 정렬**에서 드래그 또는 위/아래 버튼으로 이동할 수 있습니다. Markdown으로 직렬화하면서 공백·줄바꿈 표기가 정규화될 수 있습니다.

HTML·프런트매터·이미지·각주 등 확장 문법이 감지된 노트는 원문 모드를 유지합니다. 원문을 열었다는 이유만으로 파일을 변환하지 않습니다. 변경 전 버전은 로컬 이력에 남습니다.

### 링크

- 제목 링크는 제목 변경 시 자동으로 수정되지 않습니다.
- `[[ID|표시 이름]]`은 앱에서 만든 노트의 제목을 바꾸어도 연결을 유지합니다.
- 기존 외부 Markdown은 경로 기반 ID를 사용하므로 경로가 바뀌면 ID도 바뀝니다.

### 첨부와 가져오기

로컬 보관함에서 **첨부**로 이미지 또는 PDF를 복사해 보관합니다. 이미지 미리보기와 PDF 보기를 지원합니다. 가져오기는 Markdown·HTML을 지원하며 HTML의 실행 요소를 제거하고 Markdown으로 변환합니다.

PDF OCR, PDF 내용 편집, 조직 첨부파일 동기화는 제공하지 않습니다. 내보내기는 본문 기준이며 로컬 첨부파일 묶음 내보내기와 내부 링크 변환은 아직 지원하지 않습니다.

## 데이터와 업데이트

```text
my-vault/
├── 노트-xxxxxxxx.md       # 원본
├── assets/               # 로컬 첨부파일
└── .xdocs/
    ├── index.sqlite      # 재생성 가능한 색인
    ├── history/          # 이전 본문
    └── trash/            # 삭제한 원본
```

노트와 첨부파일은 앱 설치 위치와 분리된 보관함에 저장됩니다. 앱 코드 업데이트는 원본을 삭제하거나 초기화하지 않습니다. v0.1 보관함을 열어 색인을 갱신하고 재실행해도 원본과 ID가 유지되는 테스트를 포함합니다.

- **업데이트 전:** 저장 완료 확인 → 앱 종료 → 보관함 전체 백업.
- **개발 실행 업데이트:** 저장소에서 `git pull`, `npm ci`, `npm start`.
- **설치형 업데이트:** 설정에서 확인·다운로드·저장 후 재시작. 실제 배포된 호환 릴리스가 필요합니다. 서명된 버전 간 설치 검증은 아직 완료되지 않았습니다.
- **색인:** SQLite는 재생성 가능하지만 `.xdocs` 전체에는 이력과 휴지통도 있으므로 통째로 삭제하지 마세요.
- **설정:** 마지막 보관함 경로와 계정 관련 데이터는 Electron의 OS별 사용자 데이터 디렉터리에 보관합니다. 앱 데이터 초기화 시 폴더를 다시 선택해야 할 수 있습니다.
- **조직 변경:** 사용자 데이터 디렉터리의 `organization-data/`에 미전송 변경과 공동 편집 상태가 있습니다. 동기화 전에는 삭제하지 마세요. 보관함 폴더 백업만으로 조직의 미전송 변경까지 백업되지는 않습니다.

### 충돌과 복원

외부 파일 변경을 자동 감지합니다. 앱에서 편집 중이면 해당 초안을 유지하고 저장 시 충돌을 확인합니다. 충돌 시 **사본 저장**으로 내용을 보존할 수 있습니다. 외부 프로그램의 쓰기를 잠그지는 않으므로 동일 파일에 대한 완벽한 동시 쓰기 차단을 보장하지 않습니다.

**변경 이력**에서 이전 본문을 확인·복원합니다. **휴지통**에서 복원한 노트는 보관함 최상위에 새 이름으로 돌아옵니다. 앱에서 부여한 노트 ID는 유지됩니다.

## 조직 연결과 공동 편집

[로컬 서버 안내](server.md)에 따라 개발 서버를 준비하고 앱의 **조직 보관함 → SSO 로그인**에서 서버 주소를 입력합니다. 접근 권한이 있는 보관함만 표시됩니다. 권한은 관리자(owner), 편집자(editor), 열람자(reader)로 구분합니다.

일반 편집 내용은 기기의 영속 대기열에 저장하고 15초마다 동기화를 시도합니다. 서버 버전과 충돌하면 **조직 연결**에서 내 변경을 사본으로 남기거나 서버 버전을 선택합니다. 개인 노트는 연결만으로 공유되지 않습니다.

조직 문서의 **공동 편집**은 별도 Markdown 텍스트 편집 창을 엽니다. 약 1초 간격으로 Yjs 변경을 교환하고 동시에 수정한 내용을 병합합니다. 변경은 먼저 기기에 저장됩니다. 문서가 일반 편집으로 변경되거나 삭제되면 사본 보존을 안내합니다. 서버에 저장된 공동 편집 내용도 문서 버전에 기록됩니다.

최초 조직 연결·권한 확인에는 네트워크가 필요합니다. 이미 열린 보관함의 오프라인 편집을 지원합니다. 로그아웃은 토큰을 제거하지만 동기화되지 않은 내용 보호를 위해 조직 캐시를 삭제하지 않습니다. 캐시는 계정·서버·보관함별로 구분합니다.

토큰은 OS 보안 저장소로 암호화할 수 있을 때만 디스크에 보관합니다. Linux에서 안전한 키 저장소가 없으면 메모리에서만 사용합니다. 문서 캐시는 암호화하지 않으므로 관리 기기에서는 OS 디스크 암호화 정책을 별도로 적용해야 합니다.

## 개발 명령

| 명령                    | 역할                                            |
| ----------------------- | ----------------------------------------------- |
| `npm test`              | 저장소·업그레이드·동기화 대기열 단위 테스트     |
| `npm run build`         | 타입 검사와 프로덕션 빌드                       |
| `npm run test:ui`       | 브라우저 UI·블록 편집 검증                      |
| `npm run test:desktop`  | 빌드 후 Electron 기본 저장·내보내기             |
| `npm run test:server`   | PostgreSQL·Redis 권한·충돌·공동 편집 검증       |
| `npm run test:sso`      | 실행 중인 로컬 서버·Keycloak의 실제 로그인 검증 |
| `npm run test:features` | 빌드 후 Electron 복원·첨부·SSO·공동 편집 검증   |
| `npm run dist:dir`      | 현재 OS 실행 디렉터리 패키징                    |
| `npm run dist`          | 현재 OS 설치 파일 패키징                        |

UI 테스트 전 `npx playwright install chromium`을 실행하세요. 데스크톱 테스트는 그래픽 환경이 필요합니다. 서버 통합 테스트는 별도 임시 PostgreSQL 스키마를 만들고 제거합니다.

## 현재 제한

- 로컬 검색 결과는 최대 200개, 그래프는 최대 120개를 표시합니다. 전체 문서 목록의 메모리 최적화와 대규모 실측은 후속 검증 대상입니다.
- 5 MB 초과 문서, 숨김 폴더, 심볼릭 링크, 20단계 초과 하위 폴더는 색인에서 제외합니다. 첨부파일 제한은 25 MB입니다.
- 공동 편집 상태 제한은 4 MB이며 블록·커서 공동 편집은 포함하지 않습니다.
- 현재 서명·공증된 정식 설치 파일은 배포하지 않았습니다.

`.gitignore`는 환경변수·키·토큰·SQLite·생성 결과와 지정된 로컬 보관함 폴더를 제외합니다. 임의의 모든 Markdown 파일을 제외하는 것은 아니므로 개인 보관함은 저장소 밖에 두세요.
